# Private runtime integration kit (POL-08/09)
Status: source adapter and deletion coordinator authored; **not imported, compiled, wired or accepted in private Unity**. No live SDK dependency or credentials added to public preview. Do not enable in the shipping game until reviewed with actual private save state and Google configuration.
 
- Import official Play Games Unity v2 plugin from the official setup instructions; pin verified compatible version and dependency lock. Configure permanent package ID, app-signing SHA-1, PGS game ID, OAuth Android credential, Saved Games, test accounts and publication. No extra login.
- Copy the two C# files to private Assets after review. Invoke Authenticate once on startup and re-evaluate on foreground; preserve offline gameplay. Context ID is local partitioning only, never primary in-game authentication, never exported/logged. Adapter expects callbacks on main thread and one operation at a time.
- Bind actual native save serializer, integrity/schema checks, committed-state observer, coalesced uploads, explicit local/cloud reconciliation and conflict-choice UI. Never upload empty fresh state prior to a validated read/decision. A conflict callback must be validated by the caller before invoking choice; declining keeps pending SDK operation and local-only play until restart. Do not claim a full cloud coordinator is present.
- Construct transport with a mandatory syncPermitted callback that checks durable local profile binding and deletion barrier. The adapter checks it at operation start and asynchronous reads/conflict resolution. Before any read/commit, validate local profile binding and durable sync barrier. Never use PGS as a server-authenticated player identity. Use only game-owned snapshot slot and inventory legacy snapshots.
- CommitAcceptedNotCloudConfirmed means SDK accepted a local durable commit, not confirmed cloud replication. DeleteRequested is not deletion success; NotListed is only an observed listing state. Verify eventual sync across devices and disclose limitations; never promise irreversible server deletion solely from these statuses.
- Implement IProgressDeletionStore against actual two-generation saves, atomically preserving a per-profile barrier across relaunch, preventing all startup/restore/upload paths from resurrecting data. Persist separate cloud-deletion consent before requesting cloud deletion; local-only barrier is not consent. Add explicit UI confirmation and separate local-only / local+cloud options. No reset of unrelated profiles. Full account deletion policy requires separate review if an app account exists.
- Targeted new-feature acceptance only: authentication/fallback, profile switch, conflicts, invalid state, fresh restore, durable barrier, in-flight save/delete, deletion retries, second-device stale state and privacy links. Existing 20-match soak remains historical evidence, not repeated.
